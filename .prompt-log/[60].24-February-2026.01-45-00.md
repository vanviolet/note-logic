## Prompt
1. PM dan LR masih error di alphaTeX ("Unrecognized property 'pm'/'lr'")
2. Bug: edit note setelah import GP tidak merubah apapun
3. Import GP time signature 8/4 tapi editor menampilkan 14 beat per bar

## Point OF AI Response

### Fix 1: PM/LR/ST alphaTeX Syntax
Berdasarkan dokumentasi resmi alphaTab (`_note-properties.mdx`):
- `pm` (Palm Mute), `lr` (Let Ring), `st` (Staccato) → **NOTE-level** properties
- Harus berada di `{}` pada note (setelah string number), bukan di beat effect block
- `s` di beat level artinya **Bass Slap**, bukan staccato
- Staccato yang benar: `st`, bukan `s`

Sebelumnya kode menaruh pm/lr/s di beat effect block → `3.1.4 {pm lr}` → error
Sekarang: `3.1{pm lr st}.4` → valid

**Files**: `studio-utils.ts` (`noteToAlphaTexToken` + chord output)

### Fix 2: Edit Setelah Import GP Tidak Berubah
Root cause: Saat edit note setelah import, `useEditorScore()` dipanggil → `scoreSource` berubah ke "editor" → `api.tex(alphaTex)` di-trigger. Tetapi alphaTeX yang dihasilkan mengandung `{pm}` dan `{lr}` di beat effect block → alphaTab parser menolak tex → render gagal → tampilan tidak berubah.

Dengan fix #1, alphaTeX sekarang valid → render berhasil setelah edit.

### Fix 3: Time Signature Import (8/4 → 14 beats)
Problem: `beat.index` adalah sequential index dalam voice (0,1,2,...13 untuk 14 eighth notes), bukan posisi ritmis. `gridStepsPerMeasure` diexpand ke 14 berdasarkan `maxBeatIndexInAnyBar + 1`.

Solusi:
- Gunakan `beat.playbackStart` (tick offset dari awal bar) untuk menghitung posisi grid cell
- 1 grid cell = 1 quarter note = 960 ticks
- `cellIndex = Math.floor(playbackStart / 960)`, capped at `timeSignatureNumerator - 1`
- `gridStepsPerMeasure` selalu = `timeSignatureNumerator` (tidak di-expand)
- Dua eighth notes di quarter yang sama → dipetakan ke cell yang sama (treated as chord, first one wins per string)

### Also: PM/LR/ST now note-level in updateNoteById
Moved `isPalmMute`, `isLetRing`, `isStaccato` from beat-level to note-level updates, matching alphaTeX semantics.
