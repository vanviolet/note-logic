## Point OF AI Response

### Root Cause

The Canon GP file uses **two voices per bar**, each containing **quarter notes** (playbackDuration=960) that interleave to produce an eighth-note rhythm:

- Voice 1: playbackStart = 0, 960, 1920, 2880 (bass notes)
- Voice 2: playbackStart = 480, 1440, 2400, 3360 (melody notes)

The previous **duration-based** statistical approach only examined individual `beat.playbackDuration` values. Since ALL beats are quarter notes (pd=960), it chose `cellTicks=960` → only 4 grid steps per bar → voice 2 notes overlapped with voice 1 at same grid positions → deduplicated away. Result: only half the notes appeared, on every-other position.

### Fix: Position-Based GCD Algorithm

Replaced duration-based analysis with **GCD (Greatest Common Divisor) of all non-zero playbackStart values** across ALL voices in all bars:

1. Collect all `beat.playbackStart > 0` from every voice/bar (skip rests, grace notes, empty)
2. Compute GCD: for Canon, positions include 960, 480, 1440... → GCD = **480**
3. Pick largest standard subdivision (960/480/240) that evenly divides GCD:
   - 480 % 960 ≠ 0 → skip
   - 480 % 480 = 0 → **cellTicks = 480** (eighth note)
4. gridStepsPerMeasure = 3840/480 = **8** ✅

This correctly detects that the two interleaving voices create eighth-note temporal density, even though individual beat durations are quarter notes.
