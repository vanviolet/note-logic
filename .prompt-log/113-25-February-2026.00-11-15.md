## Prompt
Ada bug ketika awal reload project yang sudah di save, kembali ke project default kemudian ketika ada perubahan baru kembali ke saved project, kemudian ketika ketik angka di notes tidak ada perubahan langsung di editornya

## Point OF AI Response

### Root Cause Analysis

Both bugs share the same root cause in `GridStringRow`'s memo comparison function:

```tsx
// studio-grid.tsx line ~1323
// Don't compare noteByCell by reference — let GridCell memo handle it
// prev.noteByCell === next.noteByCell &&
```

The `noteByCell` prop comparison was **commented out** in the previous session (#112). This means `GridStringRow` never re-renders when notes change — it only re-renders when other props like `selectedCell` change.

**Bug 1 — Project shows defaults on reload then switches back:**
- On mount, `createInitialNotes()` runs → default notes in state
- `useStudioProject` loads saved project async → `setNotes(project.notes)` → `noteByCell` gets new Map
- BUT `GridStringRow` memo skips `noteByCell` comparison → grid keeps showing old default notes
- When user interacts (e.g., clicks) → `selectedCell` changes → row re-renders → shows loaded notes

**Bug 2 — Digit input doesn't show changes:**
- User types digit → `setNotes()` updates fret → `noteByCell` gets new Map with updated fret
- BUT `GridStringRow` memo skips `noteByCell` comparison → grid doesn't re-render → stale fret displayed

### Additional Fix — Strict Mode Race Condition

In `use-studio-project.ts`, `autosaveReadyRef.current = true` was set in the `finally` block without checking the `canceled` flag. Under React Strict Mode (double-mount), the first mount's cleanup sets `canceled = true`, but the `finally` block still runs → autosave triggers with default state before the second mount loads the project.

### Changes Made

1. **`studio-grid.tsx`** — Uncommented `prev.noteByCell === next.noteByCell` in `GridStringRow` memo comparison
2. **`use-studio-project.ts`** — Guarded `autosaveReadyRef.current = true` and `setAlphaStatus` with `!canceled` check in the load effect's `catch`/`finally` blocks
