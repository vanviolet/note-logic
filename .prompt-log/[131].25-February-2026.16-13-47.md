## Prompt
Oke sudah lebih baik tapi masih agak sedikit lag, mungkin karena component fretboard ini.
Coba analisa component ini, tingkatkan performanya, dan anda boleh merubah UI ketika implementasinya dengan alasan memperbagus performa.

## Root Cause Analysis

| Issue | Impact |
|-------|--------|
| `console.log("render fretboard")` | Noise, confirms excessive re-renders |
| `NOTE_NAMES_SHARP` duplicated locally | Minor: redundant code |
| No `memo` on `Fretboard` | Parent re-render → full Fretboard re-render |
| All 78+ buttons rendered inline in parent | `activeNote` change → 78 button reconciliations |
| `buildFretNote` + `parseScientificNote` called every render | String parsing × 78 cells × every render |
| `internalTuning` useState + useEffect sync | Extra render cycle on every `tuning` prop change |
| `onFretClick` inline arrow in consumers | Breaks `memo(Fretboard)` on every card render |
| Hardcoded `grid-cols-[124px_repeat(13,...)]` | Breaks for fretCount ≠ 12 |

## Point of AI Response

### 1. `FretButton = React.memo(...)` — New subcomponent

Extracted each fret cell as a memoized `FretButton` component:
- Props: `noteData`, `isHighlighted`, `toneLabel`, `isActive`, `onFretClick`
- `isActive` and `isHighlighted` are **booleans** → O(1) memo comparison
- `noteData` is stable from `useMemo` (gridData) → `handleClick = useCallback` is stable
- **Result:** clicking a fret → only 2 FretButton re-renders (old active + new active), not 78

### 2. `FretboardStringRow = React.memo(...)` — New subcomponent

Each guitar string is an independently memo'd row:
- Receives `activeFret: number | null` (only for THIS string, not global `activeNote`)
- When `activeNote` changes string: only affected old + new rows re-render
- When `activeNote` changes fret on same string: only that 1 row re-renders, then only 2 FretButtons
- `handleTuningChange = useCallback` with stable `[onTuningSelect, row.stringIndex]` deps

### 3. `gridData = useMemo(...)` — Pre-computed note data

```tsx
const gridData = useMemo<GridRowData[]>(() => {
  return [...internalTuning].reverse().map((openString, reverseIdx) => {
    const frets = Array.from({ length: fretCount + 1 }, (_, fret) => ({
      ...buildFretNote(openString, fret),
      stringIndex,
      fret,
    }));
    return { openString, stringIndex, openLabel, frets };
  });
}, [internalTuning, fretCount]);
```

- `buildFretNote` and `parseScientificNote` now run **once** when tuning/fretCount changes
- Resulting `FretboardNote` objects are stable references → `FretButton.memo` works correctly

### 4. `memo(Fretboard)` export

```tsx
const FretboardBase = React.forwardRef<...>(...);
FretboardBase.displayName = "Fretboard";
export const Fretboard = React.memo(FretboardBase);
```

- When card parent re-renders (audio state, livePitch state changes) with same fretboard props, Fretboard itself is skipped entirely

### 5. Tuning state bypass for non-editable mode

```tsx
const internalTuning = editableTuning ? localTuning : tuning;
// useEffect only syncs when editableTuning === true
React.useEffect(() => {
  if (!editableTuning) return;
  setLocalTuning(tuning);
}, [tuning, editableTuning]);
```

- `editableTuning=false` (default) → no useState, no extra render on tuning prop change

### 6. `handleTuningSelect` stable with functional setState

```tsx
const handleTuningSelect = useCallback((idx, value) => {
  setLocalTuning(prev => {
    const next = [...prev]; next[idx] = value;
    onTuningChange?.(next); return next;
  });
}, [onTuningChange]);
```

- Doesn't depend on `internalTuning` reference → stable across renders

### 7. Dynamic grid template via inline style

```tsx
style={{
  display: "grid",
  minWidth: `${124 + (fretCount + 1) * 44}px`,
  gridTemplateColumns: `124px repeat(${fretCount + 1}, minmax(44px, 1fr))`,
}}
```

- Correctly supports any `fretCount` value
- Replaced hardcoded `min-w-[880px] grid-cols-[124px_repeat(13,...)]`

### 8. Stable `onFretClick` in consumers

In `chord-item-card.tsx` and `family-chord-card.tsx`:
```tsx
const handleFretClick = useCallback((fretNote) => {
  setActiveFret(...); setActiveFretLabel(...); playNote(...);
}, [chord.composed, playNote]); // or [entry.degree, playNote]
```

- Inline `(fretNote) => { ... }` was creating new reference every render
- Breaking `memo(Fretboard)` comparison on `onFretClick` prop every time
- Now stable: Fretboard only re-renders when props genuinely change
