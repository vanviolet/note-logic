## Prompt
Fix grid editor highlight that was completely broken during alphaTab playback — two prior attempts failed. User asked "apakah memungkinkan" (is it even possible) for duration-aware highlight synced with alphaTab.

## Point OF AI Response

**Root Cause Found: Wrong data access pattern on alphaTab's `activeBeatsChanged` event.**

The `ActiveBeatsChangedEventArgs.activeBeats` is `Beat[]` — each element IS a `Beat` directly with `.index` (position in voice) and `.voice.bar.index` (bar position). There is NO `.beat` wrapper property on `Beat`.

The handler had:
```ts
const activeBeat = args?.activeBeats?.[0];
if (!activeBeat?.beat) return; // ← Beat has no .beat → always undefined → ALWAYS early return!
```

Since `activeBeat.beat` was always `undefined`, the guard `!activeBeat?.beat` was always `true`, causing the handler to bail out on every single event. No highlighting code ever ran.

**Fix applied:**
- `activeBeat?.beat` → `activeBeat` (the element IS the beat)
- `activeBeat.beat.index` → `activeBeat.index`
- `activeBeat.beat.voice?.bar?.index` → `activeBeat.voice?.bar?.index`
- Added highlight cleanup in `playerFinished` handler
- Removed unused `playingNoteIds` and `playheadBeat` from `StudioGridProps` to prevent unnecessary React.memo-busting re-renders during playback

**Files changed:**
- `app/routes/studio/hooks/use-alpha-tab.ts` — fixed event data access, added playerFinished cleanup
- `app/routes/studio/components/studio-grid.tsx` — removed `playingNoteIds` and `playheadBeat` from props type
- `app/routes/studio/index.tsx` — removed unused prop passing, changed state to `[, setPlayingNoteIds]`
