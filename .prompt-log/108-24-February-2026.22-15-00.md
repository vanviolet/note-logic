## Prompt
"sepertinya karena banyak penambahan fitur tadi di prompt 102, terjadi banyak bug error error.txt ketika upload file gp, jadi kasusnya bisa ketika upload dan error ketika saya merubah note, sepertinya fitur fitur baru itu belum di sesuaikan dengan upload gp ya"

## Points of AI Response

### Root Cause Analysis

After importing a GP file, if the user edits a note, `useEditorScore()` switches from the imported GP score to AlphaTex-generated output via `api.tex(alphaTex)`. The `toAlphaTex()` function produced **invalid AlphaTex** due to three bugs introduced in prompt #102:

1. **Instrument names didn't match AlphaTex's valid instrument names.** `midiProgramToInstrument()` returned names like `"Acoustic Guitar (steel)"` but AlphaTex expects `"Acoustic Guitar Steel"` (no parentheses). The mismatched names caused cascading parse failures — AlphaTex couldn't recognize the instrument, leading to subsequent content being misinterpreted as percussion articulations (hence `Unexpected percussion articulation value 'the'`).

2. **Text fields (title, subtitle, artist, etc.) were not escaped.** If a GP file's metadata contained quotes (`"`), backslashes, or control characters, the AlphaTex string literals would break mid-parse.

3. **The `\track { instrument "name" }` syntax used quoted instrument name strings** that had to exactly match AlphaTex's internal lookup table — a fragile approach.

### Fixes Applied

#### `app/routes/studio/lib/studio-utils.ts`
- **Added `sanitizeTexString()`** — escapes `\`, `"`, `\n`, `\r`, `\t` inside AlphaTex double-quoted strings
- **Fixed `midiProgramToInstrument()`** — expanded from 22 entries to 88 entries, all using correct AlphaTex-compatible names (e.g., `"Acoustic Guitar Steel"`, `"Electric Guitar Jazz"`, `"Electric Bass Finger"`)
- **Added `INSTRUMENT_TO_MIDI` mapping** — comprehensive reverse lookup (display name → MIDI program number) including both current AlphaTex names AND legacy names from older saved projects
- **Added `instrumentToMidiProgram()`** — resolves any instrument name (including legacy names) to a MIDI program number, with case-insensitive fallback
- **Fixed `toAlphaTex()`**:
  - All text fields now wrapped with `sanitizeTexString()`
  - Instrument now uses MIDI program number syntax (`instrument 25`) instead of quoted name strings — this is always valid regardless of naming conventions
  - Percussion instruments handled with `instrument percussion`

#### `app/routes/studio/types.ts`
- Fixed `DEFAULT_SCORE_SETTINGS.instrument` from `"Acoustic Guitar (steel)"` to `"Acoustic Guitar Steel"`

#### `app/routes/studio/components/studio-score-settings-panel.tsx`
- Fixed all `INSTRUMENT_GROUPS` entries to use correct AlphaTex-compatible names
- Removed non-existent instruments (`"12-string Guitar"`, `"Drums"`, `"Drum Kit"`, `"Saxophone"`)
- Added missing instruments (`"Tenor Sax"`, `"Lead 5 Charang"`)
- Fixed `countChanges()` and track badge comparisons to use new default name
- Fixed instrument reset button to use `"Acoustic Guitar Steel"`

### Backward Compatibility
- Old saved projects with legacy instrument names (e.g., `"Acoustic Guitar (steel)"`) continue to work because `INSTRUMENT_TO_MIDI` includes mappings for all legacy names
- The `instrumentToMidiProgram()` function resolves legacy names correctly to MIDI program numbers for AlphaTex output
