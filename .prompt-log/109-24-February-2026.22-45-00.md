## Prompt
Analisa kenapa ketika sudah 1318 notes sangat lag sekali, apakah ada solusi untuk performance agar bagus — bahkan jika harus merubah semua state menjadi menggunakan DOM manipulation manual/useRef agar tidak ada re-render.

## Point OF AI Response

### Root Cause Analysis

When a single note is edited with 1318 notes, this cascade happens:
1. `updateNoteById` creates **1318 new objects** via `{ ...note }` for ALL notes (not just the changed one)
2. `noteByCell` useMemo rebuilds a new Map with 1318 entries
3. `toAlphaTex` scans with O(notes × measures × beats) via `.filter()` per beat
4. alphaTab re-parses entire score (300ms debounce but still heavy)
5. All GridStringRow memos break (noteByCell reference changed)
6. All GridCell components re-render (note references changed)
7. Sidebar + header + all children re-render

**One fret click = re-create 1318 objects + rebuild Map + regenerate alphaTex + re-render 1300+ components.**

### 4 Performance Optimizations Applied

**1. Structural Sharing in `updateNoteById`** (`use-studio-note-actions.ts`)
- Previously: `prev.map(note => { const next = {...note}; ... return next; })` — creates new objects for ALL notes
- Fixed: Pre-check if beat-level updates exist. Skip notes that aren't the target AND don't share the same beat with beat-level changes. Return same object reference for ~99% of notes.
- Impact: From 1318 new objects → ~1-6 new objects per edit

**2. Grid Virtualization** (`studio-grid.tsx`)
- Added `VirtualizedChunk` component using IntersectionObserver with 400px rootMargin
- Off-screen chunks render as lightweight placeholders with estimated height
- Chunks containing the selected cell are force-rendered
- Impact: From rendering ~1300+ cells → only ~150-300 visible cells

**3. toAlphaTex Pre-indexing** (`studio-utils.ts`)
- Previously: `notes.filter(n => n.measure === m && n.beat === b)` per beat = O(notes × measures × beats)
- Fixed: Pre-build `Map<number, StudioNote[]>` indexed by `measure*10000+beat`, O(1) lookup per beat
- Impact: From O(n×m×b) → O(n + m×b)

**4. Deferred Expensive Computations** (`index.tsx`)
- `useDeferredValue(notes)` for alphaTex generation and sidebar — grid stays responsive, preview/sidebar update in background
- History flags refresh via `requestAnimationFrame` instead of sync effect
- `noteByBeat` Map hoisted from StudioGrid to parent (avoids redundant computation)
- Grid receives `notesCount` (number) instead of full `notes` array for badge
- GridStringRow memo relaxed — doesn't compare `noteByCell` reference anymore; relies on GridCell-level memo with stable note refs

### Files Changed
- `app/routes/studio/hooks/use-studio-note-actions.ts` — structural sharing in updateNoteById
- `app/routes/studio/components/studio-grid.tsx` — VirtualizedChunk, relaxed GridStringRow memo, notesCount prop, noteByBeat prop
- `app/routes/studio/components/studio-main-content.tsx` — noteByBeat prop threading
- `app/routes/studio/lib/studio-utils.ts` — toAlphaTex pre-indexed notes
- `app/routes/studio/index.tsx` — useDeferredValue, noteByBeat, rAF history flags
