## Prompt
Fix runtime `alphaTab error: Error parsing alphaTex` caused by `undefined` tokens being emitted for notes created before the new optional StudioNote fields were added.

## Point of AI Response

### Root Cause
In `buildNoteLevelToken()` and `buildBeatLevelToken()` in `studio-utils.ts`, guards of the form `n.field !== "none"` evaluate to `true` when `n.field === undefined` (old notes lack the new fields). This caused literal `"undefined"` strings to be emitted into AlphaTex tokens, e.g. `tu undefined`, `tp undefined`, `gr undefined`, `fermata undefined`, `ot undefined`, etc.

### Fix Applied
Added truthy existence checks before each `!== "none"` comparison for all new optional fields:

**`buildNoteLevelToken()`**:
- `n.harmonicType && n.harmonicType !== "none"`
- `n.accent && n.accent !== "none"`
- `n.ornament && n.ornament !== "none"`

**`buildBeatLevelToken()`**:
- `n.strokeType && n.strokeType !== "none"`
- `n.arpeggioType && n.arpeggioType !== "none"`
- `n.tuplet && n.tuplet !== "none"`
- `n.tremoloMark && n.tremoloMark !== "none"`
- `n.graceType && n.graceType !== "none"`
- `n.fermata && n.fermata !== "none"`
- `n.octaveShift && n.octaveShift !== "none"`

Already-safe guards (truthy or strict equality) were left unchanged: `isTied`, `isGhost`, `isLeftHandTap`, `pickSlide`, `wahMode`, `chordName`, `beatText`.

### Files Modified
- `app/routes/studio/lib/studio-utils.ts` — guards fixed, Prettier formatting applied, no TypeScript errors.
