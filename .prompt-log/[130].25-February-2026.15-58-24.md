### 2. New `learn-layout.tsx` Route Layout

Created `app/routes/learn-layout.tsx` as a nested layout for chord/family/interval:

- **`MemoizedOutlet = memo(Outlet)`**: Prevents child route re-render when sidebar state changes. React Router context doesn't change on sidebar toggle, so memo is effective here.
- **`LearnContentWrapper = memo(...)`**: Subscribes to `useLearnSidebarStore` directly (Zustand). Updates `lg:pr-[300px]` padding when sidebar opens. Since it subscribes directly, Zustand triggers it independently without going through `LearnLayout`.
- **`LearnLayout`**: Only subscribes to `setOpen` (stable reference, never triggers rerender). Handles media query sync (lg+ → open). Does NOT subscribe to `isOpen` so it never re-renders on sidebar toggle.

### 4. `FloatingFilterSidebar` Refactored

- **Before**: Required `open: boolean` and `onToggle: () => void` as props — routes had to maintain this state.
- **After**: Reads `isOpen` and `toggle` from `useLearnSidebarStore` internally. API is now just `title` + `children`. Subscribes to Zustand directly, so it re-renders independently on toggle without requiring the parent route to re-render.

### 5. Performance: Sidebar Toggle No Longer Re-renders Card Lists

**Before** (re-render cascade on sidebar toggle):
- Route state `isFilterOpen` changes → Route re-renders → card list reconciles → expensive

**After** (isolated re-renders):
- Zustand toggle → `FloatingFilterSidebar` re-renders (shows/hides panel + changes button icon) ✓
- Zustand toggle → `LearnContentWrapper` re-renders (updates padding) ✓
- `MemoizedOutlet` inside ContentWrapper: no prop/context change → **memo prevents route re-render** ✓
- `ChordRoute`/`FamilyRoute`/`IntervalRoute` **do NOT re-render on sidebar toggle** ✓
