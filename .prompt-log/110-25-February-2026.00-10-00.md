## Point OF AI Response

### Root Cause Analysis — Playback Stutter with 1318+ Notes

Identified 5 key bottlenecks in the playback pipeline that cause audio/visual stutter:

1. **`setState` on every beat tick (~6/sec at 96 BPM)** — `setPlayheadBeat()` and `setPlayingNoteIds()` were `useState` setters called in `activeBeatsChanged` handler. Each call triggers a full React re-render of the entire StudioRoute tree (~1300 components), even though these state values are **never read in JSX** (destructured as `[, setter]`).

2. **O(n) note filtering per tick** — `notesRef.current.filter(...)` scanned all 1318 notes on every beat to find matching notes for highlighting.

3. **4× `querySelectorAll` per tick** — Clearing old highlights used 2 full DOM scans (`.studio-cell-playing` and `.studio-note-playing`), plus 1-2 more for setting new highlights.

4. **Callback refs in init effect deps** — `onPlayheadBeatChange`, `onPlayingNoteIdsChange`, `onPlaybackStateChange` were in the `useAlphaTab` init effect dependency array, risking accidental alphaTab re-initialization.

5. **`api.tex()` reparse during playback** — The debounced alphaTex effect could fire during active playback if deferred notes updated, causing the entire score to be re-parsed.

### Fixes Applied

**`app/routes/studio/index.tsx`:**
- Converted `playheadBeat` and `playingNoteIds` from `useState` → `useRef` + stable `useCallback` setters (same `React.Dispatch<React.SetStateAction<T>>` type signature, drop-in compatible with all downstream hooks)
- Added `noteIdsByBeatRef` — `Map<"measure:beat", string[]>` pre-indexed in a `useEffect([notes])` for O(1) lookup during playback
- Passed `noteIdsByBeatRef` and `isPlaybackRunning` to `useAlphaTab`

**`app/routes/studio/hooks/use-alpha-tab.ts`:**
- Replaced `notesRef` param with `noteIdsByBeatRef` for O(1) beat→noteIds lookup
- Added `cbRef` (stable callback refs pattern) — callbacks are read via ref at call time, preventing stale closures AND removing them from init effect deps
- Replaced O(n) `.filter().map()` with `noteIdsByBeatRef.current.get(key) ?? []` — O(1)
- Replaced 4× `querySelectorAll` clearing with `prevHighlightRef` — tracked array of previously highlighted elements, cleared directly in O(k) where k = ~7 elements per beat
- Stabilized init effect deps to `[hideAlphaTabAttribution, hostRef, isDarkMode, noteIdsByBeatRef]` — callbacks no longer cause re-init
- Added `isPlaybackRunning` guard to alphaTex reparse effect — `api.tex()` skipped while playback is active, auto-applied when playback stops

### Performance Impact Summary

| Metric | Before | After |
|---|---|---|
| React re-renders per beat tick | 2 (full tree, ~1300 components) | 0 |
| Note matching per tick | O(1318) filter+map | O(1) Map.get |
| DOM queries per tick | 4× querySelectorAll | 1× querySelectorAll + tracked clear |
| Init effect deps (callback) | 3 callback refs | 0 (via cbRef pattern) |
| alphaTex reparse during playback | possible | blocked |
