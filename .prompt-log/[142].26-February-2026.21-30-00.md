## Prompt
ketika saya edit sekarang malah tidak ada perubahan — after importing Canon Rock GP, note edits in the grid don't update the alphaTab preview at all. Console shows repeated `useEditorScore() SKIPPED — imported score still active`.

## Point OF AI Response

### Root Cause
The previous session's `useEditorScore(force?)` skip logic was too aggressive. It prevented ALL note edits from transitioning to editor mode, which means:
- The grid state updated (notes added/removed in React) ✓
- But `scoreSource` stayed as `"imported"` → the tex effect never fired → alphaTab preview never updated ✗

### Changes Made

**1. Removed the skip logic from `useEditorScore()` (use-alpha-tab.ts)**
- Before: `useEditorScore()` was a no-op when `scoreSource === "imported"`, only `useEditorScore(true)` worked
- After: `useEditorScore()` always transitions to editor mode. If already in editor mode, it's a no-op (early return). No `force` parameter.
- Trade-off: Once the user edits an imported GP file, sound switches from rich GP MIDI to AlphaTex-based rendering. This is inherent to alphaTab and expected behavior.

**2. Fixed initial multi-track import rendering (use-studio-project.ts)**
- Before: `importAllTracksToStudio` called `renderImportedScore(score, [0,1,2,3])` — rendered all tracks
- After: `renderImportedScore(score, [0])` — renders only the active (first) track. The sync effect in index.tsx handles subsequent track switches.

**3. Cleaned up `force` parameter remnants**
- Reverted 9 `useEditorScore(true)` calls back to `useEditorScore()` in use-studio-measure-actions.ts (7) and use-studio-project.ts (2)
- Reverted 8 type signatures from `(force?: boolean) => void` back to `() => void` in all hook files
- Simplified JSDoc to one line
