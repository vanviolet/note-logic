## Prompt
Refaktor editor studio agar sesuai dengan GP yang di-import dan alphaTab preview. Tuning EBGDAD malah tampil DADGBE, note string mapping antara editor, alphaTex, dan GP import semuanya terbalik.

## Point OF AI Response

### Root Cause Analysis
Ada 3 bug fundamental yang saling berkaitan:

1. **Tuning array tidak di-reverse saat import GP**: alphaTab menyimpan `staff.tuning` dari LOW-to-HIGH (index 0 = string paling bass/tebal), tapi editor kita menampilkan dari HIGH-to-LOW (index 0 = string paling tinggi/tipis di baris atas). Tuning tidak pernah di-reverse → label tampil DADGBE bukan EBGDAD.

2. **alphaTex string numbering terbalik**: Di alphaTex, string 1 = string paling tinggi (E4 di standard tuning). Formula lama `tuningLength - note.string` memetakan index 0 ke string 6 (paling rendah) — kebalikan dari yang benar.

3. **GP import string mapping tidak konsisten**: GP `note.string` adalah 1-based dimana 1 = string paling tinggi. Setelah tuning di-reverse, mapping yang benar adalah sederhana: `note.string - 1`.

### Changes Made (studio-utils.ts)
- **`noteToAlphaTexToken`**: `stringNo = note.string + 1` (index 0 → string 1 = highest)
- **Chord mapping**: Sama, `n.string + 1`
- **`importScoreToStudio` tuning**: Ditambah `.reverse()` setelah map dari MIDI
- **GP import string**: Disederhanakan ke `importedString - 1`
- **Removed**: `resolveImportedStringIndex` function (tidak perlu lagi, mapping sekarang deterministik)

### Verification Walkthrough
- Standard: `string:0` → "E4" row → alphaTex `string 1` ✓
- Standard: `string:5` → "E2" row → alphaTex `string 6` ✓
- Dropped D import: `staff.tuning` reversed → ["E4","B3","G3","D3","A2","D2"] ✓
- GP `note.string=1` → index 0 → "E4" row ✓
- `\tuning E4 B3 G3 D3 A2 D2` → alphaTex string 1=E4 ✓
